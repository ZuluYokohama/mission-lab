# Known assurance gaps — v0.1 public preview

This controller is experimental. Its existing tests and fixture checks do not establish complete V&V, authenticity of records supplied by an adversary, or fitness for consequential deployment.

1. Plan reconstruction shares production planning logic. Some resealed incorrect parent/revision lineage is accepted: the checker does not independently compare the revision with an archived parent. A child run can record the parent seal file hash and key id. Replay of the child does not open the parent. `matching_lineage` compares them when both directories are supplied. A holder of the signing key can still write a false lineage and sign it.
2. Observation checking does not independently authenticate recorded worker command, PID or duration against an external process observer. Some resealed contradictory metadata is accepted. The controller's own event ledger is not an independent sensor.
3. Some plan numeric fields accept Python-equal Boolean/float substitutions after resealing. Worker execution of those altered plans has not been established.
4. Replay does not yet cross-check every raw job, raw output, staged file, semantic result and event through a separate implementation. Hashes detect alteration relative to a retained manifest. The HMAC detects alteration relative to a key the verifier holds. Neither establishes authorship to someone who lacks that key. See item 14.
5. Exceptional worker wait/kill paths need stronger cleanup and evidence-finalization checks. Dependency-blocked and aborted states need independent state-machine review.
6. Primary and reference paths share the standard-library SHA-256 provider. External known vectors and a separate provider are needed for stronger independence.
7. Injected duration estimates do not model calibrated end-to-end process startup and verification overhead. No measured completion advantage is claimed.
8. Human review, independent reproduction and intended-use validation remain pending. Replay is not a new execution. Reserved buffers are not total process memory, CPU cores or energy.
9. Worker launch replaces the inherited process environment with a platform start allowlist plus per-task grants. Ambient controller variables, including credentials that were not granted, are not passed. Tests launch registered workers with a sentinel parent variable and check the mapping given to the child. This does not confine a worker that was granted a secret, block filesystem or network access, or prove the child image to an outside observer. Replay checks that recorded names stay inside the published allowlist and grants. It accepts platform names from either Windows or Linux so a receipt can be checked on the other system, and it folds case while doing so. It does not prove which of those platform names were set or the exact spelling the child reported. On Windows the executor itself matches names without regard to case and records them in uppercase. TLS trust stores, proxy names, and `XAI_API_KEY` are not start-allowlist entries. `llm:grok` with transport `xai` must be granted `XAI_API_KEY` under that exact spelling, and must grant any TLS or proxy name it needs. A granted proxy can see the bearer token on the request urllib sends. `MISSION_LAB_SEAL_KEY`, `MISSION_LAB_SEAL_KEY_FILE`, `MISSION_LAB_APPROVER_KEY`, `MISSION_LAB_APPROVER_KEY_FILE`, and `MISSION_LAB_APPROVER_KEY_DIR` cannot be granted, including under another case. That refusal is name filtering, not a file-mode check. This remains process-environment filtering, not a network sandbox.
10. `llm:grok` records one chat-completions call or one local fixture read. The receipt does not score model quality or establish that the response is true. Replay verifies hashes and the recorded conclusion and does not call the network. Package tests and CI use the fixture transport or a loopback server and do not need `XAI_API_KEY`. A live call runs only when `MISSION_LAB_GROK_LIVE=1`. The response read is capped at the declared `max_response_bytes`. Redirects are refused. The request is one user message with `stream` false. `max_output_tokens` is sent to the API and is not a local measurement of output bytes. The schedule uses `fixed_task_ns`, not a measured model latency. The model-id pattern is a syntax bound, not an availability or quality allowlist. No local weights are loaded.
11. A declared model budget accounts worst-case reservations and provider-reported token counts using prices from the profile. It is not an invoice, a payment authorization, or an energy measurement. The input bound defaults to one token per prompt byte. That is a ceiling used for the hold, not a count from the model's tokenizer. A receipt above the hold fails the task and the ledger keeps the hold; it does not record the larger reported usage, and it does not show what an unseen provider bill would have been. A call that fails after the process exists and before a fitting receipt keeps the same hold, including a launch that does not finish. A launch that fails before the process starts does not. The worker process does not enforce the budget. The controller reserves before launch and settles after the receipt. Replay checks that arithmetic and the settled receipts. It does not independently reconstruct a charged line from a provider. Profiles that omit `model_budget` do not create this ledger.

12. Planner `coordinate-list-v2` does not enumerate every admitted binding. A seed keeps a move when it is strictly better than that seed's current key, and the recorded plan is the best key among those walks. It can keep a valid plan whose list-schedule key is worse than another feasible binding when the better one changes three or more `sha256` candidates at once, or needs more than eight improving moves from every seed. It is not a proof that no better admitted binding exists. Schedule admission is unchanged: worker slots, aggregate read-buffer reservations, per-task and summed model reservations, and the `llm:grok` timeout margin. A seeded test compares it with the old enumerator on small graphs. That sample is not exhaustive. Replay of a plan that has no planner stamp still uses the old enumerator, and that path rejects graphs larger than 64 nodes. The 2048-node cap and the 20-second limit in `tests/test_planner.py` are test and validation bounds. They are not a measured speedup, a throughput rating, or a claim that every graph of that size plans in that time.

13. A merit gate evaluates a closed predicate in this process. That evaluation is not a second implementation, not a proof of merit, and not a score of model quality. Replay calls the same function on archived receipts. A matching replay shows the receipt still agrees with that function and with the archived predicate hash. It does not show that an outside observer would reach the same conclusion from other evidence. `human_approval` reads `approvals.json`, an approver id and a UTC timestamp. Without `approver_key_ids`, the file is not signed, not authenticated, and not `human_review`. When the predicate lists approver key ids, a missing or invalid HMAC stays pending and does not pass. That HMAC is not `human_review`. The manifest does not depend on a gate, and a gate has no process observation. The schedule still assigns the gate a worker slot and `fixed_task_ns`; execution does not start a process, so that slot is an estimate and not a measured duration. `spend` in a predicate is the controller ledger, not an invoice. `exit_code` is the recorded observation, not an external process observer. The pattern language is a bounded whole-string check. It is not a regular expression and not a claim about the text.

14. The run seal is HMAC-SHA256. A verifier must have the same key. A match shows the canonical manifest, and the files it hashes, are unchanged for a holder of that key. It is not a public-key signature and it does not by itself prove authorship to someone who lacks the key. The key id is a fingerprint. The key is not written into the run. This version does not implement Ed25519 or an external signer. The signature object can carry another algorithm later; an unknown algorithm fails verification. `--allow-unsigned-legacy` reports `unsigned (legacy)` and does not set `integrity_verified`. That flag also accepts a run whose signature and seal claim were both removed. A signature removed while the seal claim remains is rejected. The loader does not inspect file permission bits. A symlink key file is refused. Dropping controller key names inside the worker does not erase the operating system's initial environment block. The controller's refusal to pass those names is the control. Replay of a child does not open the parent directory.

Use disposable owned fixtures. Do not use v0.1 as a sandbox for hostile code, a proof of scheduler optimality, or a source of scientific claims beyond its recorded checks. The planned response is in VV_PLAN.md; that campaign has not yet been implemented.
